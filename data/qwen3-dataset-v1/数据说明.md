# 中文耳机评论微调数据 v1

这是为 Qwen3-1.7B 微调实验准备的合成数据，任务延续此前的耳机评论信息提取：识别评价方面、情感、原文依据与复购意愿。这次只准备数据，没有启动训练。

## 文件与用途

| 文件 | 条数 | 用途 |
| --- | ---: | --- |
| train.jsonl | 500 | 训练时用于更新 LoRA 参数 |
| validation.jsonl | 100 | 训练期间监测效果、选择训练轮次与参数；不用于梯度更新 |
| test.jsonl | 100 | 包含标准答案；确定训练方案后做最终评估，不用于选择训练方案 |
| test_inputs.jsonl | 100 | 同一测试集的无答案版本，用于给模型出题 |

前三个文件每行包含 messages 数组，角色依次为 system、user、assistant。assistant 的内容是 JSON 字符串形式的标准答案。test_inputs.jsonl 只有编号及 system/user 消息，没有 assistant 答案。这两个测试文件是同一批 100 道题，不是 200 道题。

annotated 目录保存带编号、原评论、答案、难点标签和素材来源的可读记录，便于查错。train_preview.md 和 validation_preview.md 各展示前 10 条。task_prompt.txt 沿用之前冻结的任务规范。

## 标注范围

- 方面：音质、舒适度、续航、连接、物流、客服、价格。
- 情感：正面、负面、中性、正负混合。中性是明确评价一般；没有评价时不提取该方面。
- 依据必须是评论中的连续原文片段，每个方面最多出现一次。
- 复购意愿：愿意、不愿意、未明确。不能从满意或不满直接推断复购。
- 同方面当前同时有好坏评价标正负混合；明确的前后变化以当前评价为准。
- 评论内夹带的操作指令只是评论内容，不执行。

每个集合按无方面/单方面/双方面/三方面约 10%/20%/40%/30% 构成；复购意愿按未明确/愿意/不愿意 60%/20%/20% 构成。每个集合均覆盖七个方面与四种情感的全部组合，也包含讽刺、否定、转述、时间更新、无关信息和指令干扰。

## 数据来源与适用边界

这些是程序组合人工编写的素材得到的实验样本，未经独立人工标注复核，不是真实用户评论，也不是 700 条各自独立撰写的评论。训练集使用 56 条基础评价素材，验证和测试各使用 28 条，另有每组 12 条复杂场景素材及复购等片段。素材在各自集合内会重复组合，因此措辞和结构仍较规则。

先分开编写三个集合的素材，再分别生成样本。三个集合之间没有共享完全相同的评价素材，没有相同评论；生成时还排除了与之前 53 条开发/提示示例/试训练数据的重复及较高相似候选。相似度采用去标点空白后的字符三元组 Jaccard，阈值 0.65。这种检查不保证消除语义重复。

这批数据适合学习训练、验证和测试的完整流程，并进行初步效果比较。三个集合使用同一种生成方法，模型可能学会这些素材的表达模式；测试结果不能代表对真实评论或其他商品的泛化能力。之后应补充独立采集、审核的真实评论测试集。自动检查能验证格式和依据是否来自原文，不能代替对标签语义的人工审核。

## 检查与后续操作

manifest.json 保存分布、去重记录、素材来源说明和数据文件 SHA-256；token_audit.json 保存本地 Qwen 分词器的长度检查结果。建议正式训练使用 max_length=1024，并只对 assistant 答案及结束标记计算损失，屏蔽 system、user 和 padding。

此前的 train_smoke.py 专门针对 30 条试运行样本，不能直接视为已经接入这批数据。本次没有修改那个脚本，也没有更新模型参数。

下一步：先固定当前数据，在训练前测验证集作为基线；再让正式训练脚本读取 train.jsonl，并用 validation.jsonl 监测。确定方案后才打开测试集，使用训练前后相同的推理和评分设置做一次配对比较。

## 复现

在 qwen3-finetune 环境运行 build_dataset.py 可重新生成确定性数据；运行 audit_dataset.py 可验证导出的文件并使用本地分词器检查长度。两个脚本均不训练模型。
